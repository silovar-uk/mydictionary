# 私辞典｜UX再設計：言葉の書斎
作成日：2026-11-10

## 0. 要旨
私辞典の中核は「辞書項目を保存すること」ではなく、「言葉を拾う → 見つけ直す → 育てる → 偶然再会する」を、負担を増やさず日常に組み込むこと。PCは「書斎」、スマートフォンは「ポケット」を基本体験とし、機能・データ・言葉の世界観は同じまま、操作構造を端末ごとに最適化する。

Phase 1では、PCの恒常的な左ナビゲーション、キーボード起点の横断検索、PCトップの二列構成、キーボード可視フォーカスを導入する。以後の施策は下記の検証結果で優先順位を更新する。

## 1. まず前提を疑う担当｜守
### 1.1 疑うべき前提
- **「デザインは端末共通であるべき」**：データの一貫性とUIの同一性は別。PCは探索と深い編集、スマホは瞬間記録が主な仮説。
- **「機能が多いほど価値が高い」**：機能追加は発見可能性と認知負荷を悪化させる。既存の検索・編集・偶然の発見への到達性をまず改善。
- **「今日の一語を大きく見せれば利用が増える」**：鑑賞体験と作業の開始は異なる。PCのファーストビューでは新規登録・検索も同時に見えるべき。
- **「保存できれば完成」**：検索できず、文脈を再訪できず、編集できなければ資産化されない。
- **「UI改善＝見た目の調整」**：タスク達成の時間、操作回数、中断からの復帰、データ保護がUX。

### 1.2 守るべき資産
- 「私」「拾う」「育てる」「開く」という語彙、紙・墨・朱色の世界観。
- 端末内優先の保存、オフライン記録、JSONバックアップ、同期の整合性と保護。
- 出典、なぜ気になったか、使用例などの豊富な記録構造。
- 再発見アルゴリズム（未読・久しぶり・育て中・繰り返し出現抑制）。

## 2. リサーチ担当｜調査・再調査
### 2.1 ユーザー行動を先に分ける
1. Capture：聞いた・読んだ言葉を10秒以内に仮置き。
2. Retrieve：曖昧な意味・出典から過去の言葉を再発見。
3. Develop：見出し語、解釈、出典、例文を追記し自分の言葉にする。
4. Rediscover：意図していない言葉に偶然出会い、組み合わせて着想を得る。
5. Trust：保存・同期・バックアップ状況が理解でき、不安なく使える。

### 2.2 外部根拠と適用
- Nielsen Norman Group「Beyond the Hamburger」：PCでは見えるナビゲーションが発見・利用されやすい。→ 左サイドバーに常設。
  https://www.nngroup.com/articles/find-navigation-desktop-not-hamburger/
- Nielsen Norman Group「Progressive Disclosure」：頻繁な操作を先に、稀な詳細操作を次段階へ。→ 一語保存は短く、意味や出典の編集は深く。
  https://www.nngroup.com/articles/progressive-disclosure/
- Nielsen Norman Group「UI Copy: Keyboard Shortcuts」：標準ショートカットを奪わず、発見可能な補助操作にする。→ Ctrl/⌘+K を案内し、標準の保存キーは上書きしない。
  https://www.nngroup.com/articles/ui-copy/
- W3C WAI-ARIA Modal Dialog：フォーカス移動、閉じる動作、背景操作の封止。→ native dialog で横断検索を構築。
  https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/
- WCAG 2.2：最低限のターゲットサイズ、視認できるキーボードフォーカス。→ 主要操作は44px前後、:focus-visibleを明示。
  https://www.w3.org/TR/WCAG22/

### 2.3 再調査（現行実装との照合）
- 現行 `App.tsx` はPCもモバイル下部ナビ。同じ5項目をページ下部まで操作しないといけない。
- 現行 `base.css` はページ幅を820pxに制限し、デスクトップの水平余白を活用できない。
- 現行 `TodayPage.tsx` は「今日の一語」大カードの後ろにQuickAddを配置し、PC最初の画面から記録操作が遠い。
- 現行 `search.ts` はすでに見出し語・読み・意味・文脈・出典・タグの全文検索がある。検索エンジンを作り直すより呼び出しを変える方が費用対効果が高い。
- 現行 `discovery.ts` は複数軸の再出会いを加重している。「驚き」を作る素材は既存データにある。初期のAI機能追加は不要。

## 3. 破｜UIを端末別に設計し直す
### 3.1 PC：Study（書斎）
- 1100px以上：左248pxの常時表示ナビ、上部横断検索、作業エリア最大1230px。
- 「今日」は2カラム：主役の一語と、常時見えるQuickAdd / 育て途中を並置。
- 1440px以上：辞典一覧を2カラムで見渡し、長いリストの走査量を減らす。
- すべての画面からCtrl/⌘+K：言葉・意味・出典の横断検索、結果から即開く、検索語をそのまま追加。
- 現在地をサイドバーの強調表示とaria-currentで明示。

### 3.2 スマホ：Pocket（ポケット）
- 既存の下部5タブは継続。片手での「拾う」を優先。
- 「今日」は一語→入力→余白→最近という自然な一列フローへ。
- 横断検索はタップでも利用可能。キーボードショートカットの暗記は不要。

### 3.3 共通：検索と保存をひと続きに
- わかる語はすぐ開く。
- 見つからない語は検索語をそのまま新規登録できる。
- 「辞典」「拾う」「今日」へ戻る導線を明示し、意図しない画面遷移を減らす。
- 登録済みデータや同期状態の構造は変更しない。

## 4. 離｜予想外だが筋の通る体験を開発
### 4.1 仮説：辞書の価値は「単語」より「言葉間の距離」にある
例：「余白」と「経営資源」は別の文脈で保存していても、あとで二語を並べたとき新しい考えが生まれることがある。
→ **ことばの橋**（提案）：偶然選ばれた二語に、出会いの文脈・タグ・自分のメモを横並びで見せる。「この二語の関係を一行で書く」だけ促す。AIによる正解生成はしない。
- 根拠：現行の `OpenPage` には「この二語のあいだに、何がある？」という未発展の導線がある。
- 判断：Phase 1で実装しない。まず検索・登録・編集を改善し、再発見が使われるか確認する。

### 4.2 提案：入力を強制しない「未完成さの可視化」
- 言葉の閲覧時、空欄すべてを埋めさせず「あと一行だけ書く」導線を提示。
- 未完成カードを責める評価・スコアリングは避ける。
- ひとことの追加を「辞書を育てる」体験に変える。

## 5. 実装手順担当｜優先順位・スコープ・完成条件
|段階|仕様|ユーザー価値|主な完成条件|
|---|---|---|---|
|P0 今回|PC左ナビ＋横断検索＋今日の二列化＋フォーカス表示|どこからでも見つける・すぐ残す|型検査・テスト・ビルド成功、既存保存維持、モバイル表示破壊なし|
|P1 次回|辞典の一覧と詳細の二画面（PC）、編集中も前後移動|複数語を比較しながら育てる|一覧条件とスクロール位置維持、無破壊編集、Esc操作|
|P1 次回|登録フォームの必須欄と詳細欄の段階開示|入力負荷を下げる|見出し語のみ登録可能、復元可能な下書き|
|P1 次回|同期ステータスとバックアップ導線の統合|安心して継続利用|未同期がわかる、データ消去なし、別端末で再現可能|
|P2 仮説検証後|二語の「ことばの橋」|偶然から洞察を得る|実際に新しいメモが書かれた割合を計測|
|P2 仮説検証後|関連語と出典の関係表示|文脈の再利用|選んだ語に誤関連を強制しない|

## 6. UX評価のためのタスク
利用者数値を測っていないため、以下は現状実績でなく**検証目標**。
- PCで特定の言葉を探して開く：Ctrl/⌘+Kから3秒以内（候補のある場合の目標）。
- 別の画面から新規登録画面を開く：1アクション。
- 新規登録：見出し語だけなら入力→保存で完了。
- 絞り込み・並べ替え・詳細閲覧後に一覧へ戻ると、元の検索条件を失わない。
- スマホ・PCで幅320、390、768、1100、1440、1920pxの想定画面を確認。
- キーボードのみで検索を開く、選ぶ、閉じる、フォーカス復帰。
- 日本語IME入力、長い見出し語、多数の辞書項目、低速通信、オフラインで破綻しない。
- 更新があっても入力内容やIndexedDBを消さない。UI変更でDBを移行しない。

## 7. 検証の順序
1. 静的検査：TypeScript、Vitest、Viteビルド。
2. 視覚検証：PC・スマホ複数ブレークポイント、ズーム200％、キーボード操作。
3. 実機検証：Windows Chrome/Edge、iPhone SafariとPWA。
4. 実利用検証：新規単語登録、全文検索、同期前後の閲覧、下書き復元。
5. 施策評価：定性的には「迷った箇所」、定量的には到達時間・完了率・操作数と再訪率。

## 8. 非目標と守るべき安全性
- 既存DB、エントリー、同期方式、暗号化キー、バックアップ形式を変更しない。
- 表示のためだけにAI生成を追加しない。
- キーボードショートカットを唯一の操作手段にしない。
- 標準ショートカット（Ctrl+Sなど）を上書きしない。
- PCの高密度化でスマホの片手操作を犠牲にしない。
